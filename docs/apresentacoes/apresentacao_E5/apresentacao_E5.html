5.2 — orquestração: o grafo de verdade

scripts/grafo.py — StateGraph (LangGraph) ligando os 5 agentes, com loop de correção formal

mesma estrutura do grafo documentada em docs/entregas/E5/design.md — toda rota termina em execucao_resposta; MAX_TENTATIVAS = 3

loop_correcao // tentativas

  • 1 único contador (ctx.tentativas), compartilhado entre os 2 motivos de retorno: reprovação do Validador e erro de execução do Postgres
  • limite MAX_TENTATIVAS = 3 — ao esgotar, roteia pra "não consegui responder" em vez de tentar pra sempre
  • cada retentativa do Gerador de SQL limpa o estado da tentativa anterior antes de gerar de novo

bug.log // self-found

  • achado durante a construção (dry-run, antes do commit)
  • a aresta de saída checava erro_execucao, nunca limpo no self-loop "esgotado" → GraphRecursionError
  • corrigido checando resposta_final (só setado depois que a resposta de fato é escrita)

Pergunta: "qual foi a receita de 2017?"

Historico:
  - orquestrador: classificou a intencao como 'dado'
  - semantico_rag: buscou 3 trecho(s) de contexto
  - gerador_sql: gerou SQL (tentativa 1)
  - validador: SQL aprovado
  - execucao_resposta: SQL executado, 1 linha(s)
  - execucao_resposta: resposta final gerada

Resposta final:
A receita total em 2017 foi de R$ 5.962.902,01.
Esta informacao corresponde ao resultado da consulta:

SELECT ROUND(SUM(oi.price), 2) AS receita
FROM dw.orders o
JOIN dw.order_items oi ON oi.order_id = o.order_id
WHERE o.order_status = 'delivered'
  AND o.order_purchase_timestamp >= '2017-01-01'
  AND o.order_purchase_timestamp <  '2018-01-01';

Fonte: "Qual foi a receita total em 2017?" (dicionario semantico).
